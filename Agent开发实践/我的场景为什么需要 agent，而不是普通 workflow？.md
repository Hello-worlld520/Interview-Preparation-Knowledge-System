# 我的场景为什么需要 agent，而不是普通 workflow？

我觉得agent和普通工作流的最大的区别就是控制权在谁的问题。工作流是我提前定好了规则，定好了流程，就按这个流程走。然后Agent呢，是我把这个我的控制权相对来说去放权给这个智能体，让这个模型去判断它应该怎样做。

那现有的能通过工作流解决的问题，我觉得不需要去为了用agent而用agent。

当我们面对一些原来没有办法一概而就地去用固定流程来解决的问题的时候，我们就可以尝试使用agent，比如说它有复杂的决策，它有难以维护的规则，它非常依赖非结构化数据这些东西。

- **复杂的决策**工作流程涉及细致的判断、例外情况或对上下文敏感的决策，例如客户服务工作流程中的退款批准。

* **难以维护的规则**系统由于规则集庞大而复杂而变得笨拙，导致更新成本高昂或容易出错，例如执行供应商安全审查。

- **严重依赖非结构化数据。** 涉及解释自然语言、从文档中提取含义或与用户进行对话式交互的场景，例如处理房屋保险索赔。
